Each PHP file in `traits-for-class-wordpress-app/` declares a single PHP `trait wpcd_wpapp_*` (e.g. `wpcd_wpapp_admin_column_data`, `wpcd_wpapp_script_handlers`, `wpcd_wpapp_multi_tenant_app`, `wpcd_wpapp_backup_functions`, `wpcd_wpapp_tabs_security`, `wpcd_wpapp_commands_and_logs`) that is composed into the central `WPCD_WORDPRESS_APP` class defined in `class-wordpress.php`. The traits are organized by concern rather than by layer:
- Admin UI: `admin-columns.php` hooks into `manage_wpcd_app_posts_columns` / `wpcd_app_server_table_content` to render domain, SSL, PHP, cache, staging, health, and web-server-type columns.
- Remote execution: `script-handlers.php` maps every `.txt` script name to success substrings via `is_ssh_successful()` and builds placeholder arrays (`SCRIPT_URL`, `CALLBACK_URL`, `SIMPLE_STACK_ADMIN_IP`, etc.) per script; `commands-and-logs.php` drives async execution through `execute_ssh` + cron-fetched logs and posts `in-progress` meta on both `wpcd_app` and `wpcd_app_server` records.
- Domain operations: `backup.php` resolves per-app vs global S3 credentials; `push-commands.php` and `upgrade.php` orchestrate site push/upgrade flows.
- Multi-tenancy: `multi-tenant-app.php` owns template/version/tenant metadata (`wpcd_is_template_site`, `get_mt_version`, `clone_mt_metas`) and is gated behind `wpcd_is_mt_enabled()`.
- Security: `tabs-security.php` provides `wpcd_wpapp_user_can` / `wpcd_wpapp_server_user_can` / `wpcd_wpapp_site_user_can` that gate actions by capability or post authorship.
Dependency direction is one-way: traits depend on the host class's getters (`$this->get_app_name()`, `$this->get_command_url()`, `$this->execute_ssh()`) and on global WPCD helpers (`WPCD_POSTS_APP`, `WPCD_COMMAND_LOG`, `wpcd_get_option`, `wpcd_user_can`); they do not expose interfaces back to the rest of the app beyond their public methods.
