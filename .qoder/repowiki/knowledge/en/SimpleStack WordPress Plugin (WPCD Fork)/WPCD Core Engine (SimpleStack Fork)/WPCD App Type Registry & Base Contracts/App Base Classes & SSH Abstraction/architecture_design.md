Three sibling base classes form the foundation of the app/provider layer:
- `WPCD_APP` (class-wpcd-app.php) extends `WPCD_Base` and is the abstract parent for concrete apps (e.g. WordPress). It wires admin hooks (`post_row_actions`, `admin_enqueue_scripts`, `rwmb_meta_boxes`, `save_post`), registers a public REST callback route at `{app_name}/v{WPCD_REST_VERSION}/command/{id}/{name}/{status}/{cmdid}/`, manages per-app temp script storage under `wp-content/uploads/wpcd_app_{app_name}/scripts/`, resolves the active provisioning-script version via `get_configured_scripts_version()` (defaulting to `v2` with backward-compat fallbacks), and exposes token replacement helpers (`replace_script_tokens`, `add_custom_field_tokens_to_script`). It also provides SimpleStack-specific hardening: `get_simplestack_admin_ip()` validates IPv4/IPv6/CIDR before interpolation into Bash, and `get_post_site_install_plugins()` filters/sanitizes plugin slugs for the `simplestack_post_site_install` hook.
- `WPCD_APP_SETTINGS` (class-wpcd-app-settings.php) is an empty placeholder parent class for per-app settings subclasses — a stable extension point without behaviour.
- `WPCD_SSH` (class-wpcd-ssh.php) wraps phpseclib3 (`SSH2`, `SFTP`, `PublicKeyLoader`, `EC`) to execute remote commands, upload/download files, and generate Ed25519 keypairs. It centralises login failure, timeout negotiation (callback vs. long-running), result logging via `WPCD_POSTS_SSH_LOG()`, and user-name overrides through `wpcd_exec_ssh_user` / `wpcd_download_ssh_user` / `wpcd_upload_ssh_user` filters.

Dependency direction inside the module: `WPCD_SSH` depends only on phpseclib3 and global WPCD helpers; `WPCD_APP` depends on `WPCD_SSH` indirectly (via child apps) and on `WPCD()` for providers and option access; neither file requires the other directly. Concrete app classes extend `WPCD_APP` and override `add_app()` plus any metabox/script logic.
