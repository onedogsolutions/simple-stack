The `includes/core/` directory is the plugin's shared runtime that every other layer depends on. Wiring happens through `wp-cloud-deploy.php`, which registers global hooks (admin menus, React assets, roles, capabilities) via `class-wpcd-setup.php` and `functions.php`. Children communicate through three cross-cutting contracts rather than direct coupling:
- Post-type model contract (`post_type_models`): all entities (apps, servers, teams, logs) extend `class-wpcd-posts-base.php` and are discovered by the setup/bootstrap.
- Cloud-provider contract (`cloud_providers`): providers implement `class-cloud-provider-api.php` so the `app_types` layer can provision servers without knowing vendor details.
- App-type contract (`app_types`): apps extend `class-wpcd-app.php` and register scripts/tabs; the `rest_api` controllers dispatch requests to the matching app class.
The `custom_table_dns` layer sits alongside these as an independent model set (DNS provider/zone/record) with its own MetaBox registrations and API, not tied to the app/server post types. The `shared_core` base classes (`class-wpcd-base.php`, helpers in `functions*.php`) provide the common utilities (options, permissions, strings, crypto, KSES) consumed uniformly by every child.
