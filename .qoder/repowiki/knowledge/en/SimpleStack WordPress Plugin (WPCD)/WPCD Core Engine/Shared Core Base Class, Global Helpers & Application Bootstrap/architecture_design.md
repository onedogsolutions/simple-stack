Three cooperating entry points under `includes/core/`:
- `class-wpcd-base.php` defines `WPCD_Base`, a lightweight ancestor class offering shared helpers (`add_deferred_action_history`, `get_formatted_custom_links`) used by other domain classes.
- `functions.php` is a flat namespace of global helpers prefixed with `wpcd_`: post/CPT queries, option accessors (`wpcd_get_option`, `wpcd_get_early_option`, `wpcd_set_option`), nonce validators, string/line utilities, role/permission lookups (`wpcd_user_can`, `wpcd_get_posts_by_permission`), and feature-gate checks for authors (`wpcd_can_author_view_server_feature`, `wpcd_can_author_view_site_feature`).
- `wp-cloud-deploy.php` defines `WP_CLOUD_DEPLOY`, the application singleton (via `instance()` + `$GLOBALS['WP_CLOUD_DEPLOY']`) that bootstraps the plugin: registers custom post types through lazy instantiation in `setup_post_types()`, loads roles/capabilities, hooks into `admin_menu` / `admin_enqueue_scripts` / `parent_file` / `submenu_file`, renders the SimpleStack React container, and manages the Vite build manifest at `assets/dist/.vite/manifest.json`. It also holds the provider registry (`$providers` keyed by slug) and exposes filters like `wpcd_get_cloud_providers` and `wpcd_os_list` so extensions can mutate behavior.

Dependency direction is one-way: `wp-cloud-deploy.php` depends on `functions.php` helpers; `class-wpcd-base.php` is independent and consumed by both. The module does not depend on any sibling domain classes except via lazy instantiation inside `WP_CLOUD_DEPLOY::setup_post_types()`.
