Single-namespace REST surface under `simple-stack/v1` (defined in `SimpleStack_REST_Controller_Base::NAMESPACE`). `class-simplestack-rest-api.php` is the registrar: it hooks `rest_api_init`, loads controller files via a static `load_files()` list, instantiates each controller class, verifies it extends `SimpleStack_REST_Controller_Base`, and calls its `register_routes()`. Concrete controllers (`Servers`, `Sites`, `Logs`, `Tabs`, `Providers`, `Security`) extend the base and register routes through protected helpers (`register_get_route`, `register_post_route`, `register_delete_route`). The base enforces a uniform permission model — every route uses `permissions_check()` which requires `manage_options`, so no public permission callback is allowed. All responses go through `respond()`, which wraps data in `{ ok, data, meta }` and runs the payload through `SimpleStack_Secret_Redactor` to scrub secrets before they reach the browser. Parameter validation is centralized via typed helpers (`arg_id`, `arg_int`, `arg_string`, `arg_text`, `arg_object`, `arg_params`) that pair a `sanitize_callback` with a `validate_callback`; paging is normalized by `paging()`/`paging_args()` with a hard cap at `MAX_PER_PAGE = 200`. A legacy compatibility bridge (`dispatch_tab_action`) maps modern JSON params back onto `$_POST`/`$_FILES` and dispatches through the existing `wpcd_app_*_tab_action` filter chain, preserving SSH key and file-upload quirks for older tab handlers.
