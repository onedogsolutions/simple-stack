Two parallel class hierarchies under this directory:

- Model layer (root files): `WPCD_MB_Custom_Table` in `class-wpcd-custom-table.php` is an abstract base that wires MetaBox/CustomTable integration — model registration via `mb_register_model`, table creation via `MetaBox\CustomTable\API::create`, admin menu, inline add/edit AJAX hooks (`wp_ajax_wpcd_{model}_inline_edit|add|save_inline_edit|delete_item`), nonce handling, permission checks, and public/admin page dispatch. Concrete models `WPCD_CT_DNS_Provider`, `WPCD_CT_DNS_Zone`, `WPCD_CT_DNS_Zone_Record` extend it, each overriding `register_model()`, `create_table()`, `metaboxes()`, and optionally `validate_data()` / `ajax_handle_delete_item()`.
- API layer (`api/`): `WPCD_Custom_Table_API` provides shared CRUD, meta storage on a shared `wpcd_ct_model_meta` table, permission-scoped listing (`get_items_by_permission` joins owner + `allowed_roles`/`allowed_users`), and a static `get($model_name)` factory resolving `WPCD_CT_{Model}_API`. Each model has a matching API subclass (`dns_provider_api`, `dns_zone_api`, `dns_zone_record_api`) plus a generic `WPCD_CT_Provider_API` and `WPCD_Custom_Table_API`.
- UI helpers: `class-wpcd-ct-list-table.php` and `class-wpcd-ct-childs-list-table.php` render admin tables; `class-ct-admin.php` registers the admin menu entry. Child tables for zones/records are rendered inside the parent provider metabox via `child-items-mb` metaboxes and loaded through dedicated `wp_ajax_*` endpoints.

Dependency direction: concrete models depend on the base model and their own API subclasses; models cross-reference siblings only via `WPCD_MB_Custom_Table::get('dns_zone'|'dns_zone_record')` to cascade deletes or embed child tables. The base model depends on the external MetaBox CustomTable library and on global `wpcd_is_admin()` / `rwmb_request()` helpers from the surrounding plugin.
