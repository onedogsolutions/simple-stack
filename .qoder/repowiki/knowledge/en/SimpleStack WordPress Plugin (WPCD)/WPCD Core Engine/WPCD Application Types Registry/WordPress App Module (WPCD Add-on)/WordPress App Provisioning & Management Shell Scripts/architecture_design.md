Two parallel versioned trees (`v1/` and `v2/`) mirror the same layout: a top-level flat collection of `.txt` shell scripts (each named after its operation, e.g. `install_wordpress_site.txt`, `backup_restore.txt`, `manage_https.txt`) plus a `raw/` subdirectory containing the canonical source fragments that are stitched together at build time, and a `multi-tenant-pre-post-samples/` directory with user-overridable lifecycle hooks for multi-tenant site conversion/upgrade.

Dependency direction is one-way: every operational script sources `raw/9999-common-functions.txt` (and sometimes `wp-backup2-helper`, `wp-sync`, or `environment variables`) for shared functions like `gf_*` / `g_*` helpers, space checks, cache flushing across multiple WP caching plugins, and LiteSpeed/Olson Server detection. The `run_upgrades_*.txt` and `run_upgrade_install_php_8[123].txt` files act as thin upgrade entry points that dispatch to numbered upgrade fragments in `raw/`. Multi-tenant samples follow the same pattern in both versions.

The `.txt` extension signals these are template payloads — placeholders such as `##SCRIPT_NAME##`, `##DOMAIN##`, `##CALLBACK_URL##` are substituted by the PHP engine before execution, and scripts terminate by invoking a `CALLBACK_URL` HTTP endpoint to report status back to the parent process.
