Controllers are layered under a single abstract base `WPCD_REST_API_Controller_Base` (`class-wpcd-rest-api-controller-base.php`) which registers routes via `rest_api_init`, enforces admin-only access through `wpcd_is_admin()`, wraps every action in `build_callback()` to normalize responses with `rest_ensure_response()` and convert thrown exceptions into `WP_Error` responses (with optional `disable_status_code` query param). Concrete controllers extend this base:
- `WPCD_REST_API_Controller_Servers` — CRUD over `wpcd_app_server` posts under `/servers`.
- `WPCD_REST_API_Controller_Sites` — CRUD plus `toggle-ssl` and `execute-action` over `wpcd_app` posts under `/sites`.
- `WPCD_REST_API_Controller_Tasks` — read-only listing of `wpcd_pending_log` entries under `/tasks`.
- `WPCD_REST_API_Controller_Sites_Change_Domain` and `WPCD_REST_API_Controller_Sites_Clone_Site` extend `Sites` to add sub-routes `/sites/{id}/change-domain` and `/sites/{id}/clone-site` respectively.

Long-running operations (server creation, WP install, domain change, clone) follow a consistent pattern: the controller writes a pending-task record via `WPCD_POSTS_PENDING_TASKS_LOG()->add_pending_task_log_entry()` and returns a `task_id`; a background process later fires an action hook (e.g. `wpcd_wordpress-app_rest_api_install_wp`, `wpcd_wordpress-app_rest_api_pending_log_change_domain_full_live`, `wpcd_wordpress-app_rest_api_pending_log_clone_site`) that the same controller listens for, executes the real operation, and updates the pending log to `complete` or `failed`. Success/failure hooks (`*_completed_after_cleanup`, `*_site_change_domain_failed|completed`, `*_clone_site_failed|site_clone_new_post_completed`) close out the task. Dependency direction is one-way: controllers depend on `WPCD_WORDPRESS_APP()`, `WPCD_SERVER()`, and `WPCD_POSTS_PENDING_TASKS_LOG()` globals; nothing in this module is imported by them.
