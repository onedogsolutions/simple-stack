- Each tab is a single PHP file declaring one class that extends `WPCD_WORDPRESS_TABS` and registers itself via the `wpcd_app_{$this->get_app_name()}_get_tabnames` / `_get_tabs` / `_tab_action` filter trio in its constructor.
- Tab visibility is gated by a `get_tab_security($id)` method that combines team permission checks (`wpcd_wpapp_site_user_can` / `wpcd_wpapp_server_user_can`) with author-level tab access (`wpcd_can_author_view_site_tab` / `wpcd_can_author_view_server_tab`).
- AJAX actions are whitelisted in an explicit `$valid_actions` array inside `tab_action()` before any switch dispatch, and unauthorized attempts return a localized `WP_Error` containing the action name, file basename, post id, and current user id.
- Declarative action metadata is returned from `get_actions()` as a keyed array of metabox.io-compatible field definitions (with `label`, `type`, `raw_attributes`, optional `confirmation_prompt`, `data-wpcd-fields`, etc.), then rendered generically by the base class's `get_fields_for_tab()`.
- Server-side work is executed through `execute_ssh('generic', $instance, ['commands' => ...])` after building commands via `turn_script_into_command()` against a named bash script, with results validated via `is_ssh_successful()`.
- Long-running or multi-step operations are queued through `WPCD_POSTS_PENDING_TASKS_LOG()->add_pending_task_log_entry()` and later processed via dedicated `wpcd_pending_log_*` action hooks rather than blocking the request.
