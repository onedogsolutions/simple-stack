- Front-end page detection is centralized in static helpers on `WPCD_WORDPRESS_APP_PUBLIC` (`is_app_edit_page`, `is_server_edit_page`, `is_apps_list_page`, `is_servers_list_page`, `is_public_page`) rather than checking `$post` inline.
- List-table rendering follows a base-class + subclass pattern: a shared `WPCD_Public_List_Table` provides query, pagination, views, and grid rendering, while each screen (`Servers_List_Table`, `WPCD_Server_Apps_List_Table`) only sets its `post_type`, columns, row actions, and no-items message.
- Grid-responsive table output is implemented via the reusable `wpcd_grid_table` trait, which replaces the default `<table>` with CSS-grid divs and emits per-column `minmax(...)` styles through `grid_template_columns`.
- Shortcodes return their markup wrapped in `<div id="wpcd_public_wrapper">...</div>` so the front-end container styling is uniform across all public screens.
- AJAX mutations go through a single dispatcher method (`ajax_public`) that validates `_action`, `id`, and nonce against whitelists before delegating to trash/delete/restore handlers, then re-hooks the original `wp_trash_post`/`before_delete_post` callbacks afterward.
- Optional features are loaded lazily via `require_once` inside methods (e.g., `servers_shortcode`, `server_apps_shortcode`, `mb_custom_table_load`, `rwmb_meta_box_class_name`) guarded by `class_exists` or option checks instead of being autoloaded at boot.
