The module is an add-on to the parent WPCD plugin: `functions-classes-wordpress-app.php` registers singleton instances of post-type classes (`WPCD_SITE_PACKAGE`, `WPCD_APP_UPDATE_PLAN`, `WPCD_POSTS_QUOTA_PROFILE/LIMITS`) into the global `WPCD()->classes` array on `init`, which is the cross-child contract for sharing state between the admin tabs, REST controllers, and public UI. The main orchestrator `class-wordpress-app.php` composes behavior via traits under `traits/traits-for-class-wordpress-app/` (backup, commands-and-logs, push-commands, script-handlers, multi-tenant, upgrade) that are reused by both site-level and server-level tab handlers. Child layers communicate through this registry plus the REST API layer (`rest-api/`) which exposes server/site/task endpoints consumed by the JS assets; the `scripts/v1` and `scripts/v2` directories hold parallel bash template sets (one per API version) that the PHP side pushes to remote servers. Assets under `assets/` are enqueued by the public/admin entry points and target either the admin app screens or the front-end help popup rendered from `templates/`.
