Three sibling base classes under `includes/core/apps/` form the foundation for every concrete app:
- `WPCD_APP` (`class-wpcd-app.php`) extends `WPCD_Base` and is the primary abstract app. It owns the app identity (`app_name`, `app_desc`, `scripts_folder`, `scripts_folder_relative`), registers WordPress hooks (REST endpoint, admin enqueue, Metabox.io metaboxes, row actions), implements the long-running command lifecycle via transients keyed on `wpcd_command_{app}_{id}_{name}`, exposes a public REST callback at `/wp-json/{app}/v{version}/command/{id}/{name}/{status}/{cmdid}/`, provides script loading with provider-prefixed fallbacks, token replacement (`##TOKEN##`), temp-script upload directory management, and cloud-provider region/size helpers.
- `WPCD_APP_SETTINGS` (`class-wpcd-app-settings.php`) is an empty parent class that concrete app settings classes extend — it exists purely as an inheritance anchor.
- `WPCD_SSH` (`class-wpcd-ssh.php`) wraps phpseclib3 (`SSH2`, `SFTP`, `RSA`, `EC`, `PublicKeyLoader`) to provide `exec()`, `download()`, `upload()`, `create_key_pair()` (Ed25519) against remote servers, handling key decryption via `WPCD()->decrypt()`, timeout negotiation, error formatting, and logging through `WPCD_POSTS_SSH_LOG`.

Dependency direction: concrete apps depend on these three bases; the bases depend on the global plugin facade `WPCD()`, on shared services like `WPCD_POSTS_COMMAND_LOG`, `WPCD_POSTS_SSH_LOG`, `WPCD_CUSTOM_FIELDS`, and on WordPress APIs. The REST callback is intentionally public but gated by a transient lookup of the expected command attributes, so only commands the site actually initiated can report back.
