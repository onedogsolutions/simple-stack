Each PHP file in `traits-for-class-wordpress-app/` declares a single PHP `trait sstk_wpapp_*` (e.g. `sstk_wpapp_admin_column_data`, `sstk_wpapp_script_handlers`, `sstk_wpapp_multi_tenant_app`, `sstk_wpapp_backup_functions`, `sstk_wpapp_tabs_security`, `sstk_wpapp_commands_and_logs`) that is composed into the central `SSTK_WORDPRESS_APP` class defined in `class-wordpress.php`. The traits are organized by concern rather than by layer:
- Admin UI: `admin-columns.php` hooks into `manage_sstk_app_posts_columns` / `sstk_app_server_table_content` to render domain, SSL, PHP, cache, staging, health, and web-server-type columns.
- Remote execution: `script-handlers.php` maps every `.txt` script name to success substrings via `is_ssh_successful()` and builds placeholder arrays (`SCRIPT_URL`, `CALLBACK_URL`, `SSTK_ADMIN_IP`, etc.) per script; `commands-and-logs.php` drives async execution through `execute_ssh` + cron-fetched logs and posts `in-progress` meta on both `sstk_app` and `sstk_app_server` records.
- Domain operations: `backup.php` resolves per-app vs global S3 credentials; `push-commands.php` and `upgrade.php` orchestrate site push/upgrade flows.
- Multi-tenancy: `multi-tenant-app.php` owns template/version/tenant metadata (`sstk_is_template_site`, `get_mt_version`, `clone_mt_metas`) and is gated behind `sstk_is_mt_enabled()`.
- Security: `tabs-security.php` provides `sstk_wpapp_user_can` / `sstk_wpapp_server_user_can` / `sstk_wpapp_site_user_can` that gate actions by capability or post authorship.
Dependency direction is one-way: traits depend on the host class's getters (`$this->get_app_name()`, `$this->get_command_url()`, `$this->execute_ssh()`) and on global SSTK helpers (`SSTK_POSTS_APP`, `SSTK_COMMAND_LOG`, `sstk_get_option`, `sstk_user_can`); they do not expose interfaces back to the rest of the app beyond their public methods.
