Controllers extend a single abstract base class `WPCD_REST_API_Controller_Base` which owns the shared `wpcd/v1` namespace, registers routes via `rest_api_init`, enforces admin-only access through `wpcd_is_admin()`, wraps every action in a try/catch that converts thrown `Exception`s into `WP_Error` responses (with optional `disable_status_code` query param), and provides helpers like `validate_required_parameters` and `validate_author_email`. Each concrete controller (`Servers`, `Sites`, `Tasks`, plus `Sites_Change_Domain` and `Sites_Clone_Site`) declares a protected `$name` property that forms its sub-path (e.g. `/servers`, `/sites/{id}`) and implements `register_routes()` using convenience methods `register_get_route` / `register_post_route` / `register_put_route` / `register_delete_route`. Controllers do not perform provisioning directly — they delegate to existing WPCD services (`WPCD_SERVER()`, `WPCD_WORDPRESS_APP()`, `WPCD_POSTS_PENDING_TASKS_LOG()`) and coordinate long-running work by creating pending-task log entries (`rest_api_install_wp`, `rest_api_install_server`) and subscribing to WPCD command-completed hooks (`wpcd_command_wordpress-app_prepare_server_completed`, `wpcd_command_wordpress-app_completed_after_cleanup`) to mark tasks complete. The dependency direction is one-way: controllers depend on the broader WPCD app engine; nothing inside this directory is imported by the engine.
