- Each tab is a single PHP file declaring one class extending `SSTK_WORDPRESS_TABS` (or `SSTK_WORDPRESS_TABS_SERVER_*` for server tabs) whose constructor attaches the tab via the `*_get_tabnames`, `*_get_tabs`, and `*_tab_action` filters scoped to `{$this->get_app_name()}`.
- Tab visibility is gated by implementing `get_tab_security($id)` which combines a team permission check (`sstk_wpapp_site_user_can` / `sstk_wpapp_server_user_can`) with an author-level check (`sstk_can_author_view_site_tab` / `sstk_can_author_view_server_tab`).
- Action handlers first call `sstk_user_can_view_wp_app` / `sstk_user_can_view_wp_server`, then whitelist the action in a local `$valid_actions` array before re-checking `get_tab_security`, returning a translated `WP_Error` on failure.
- UI output is built as a metabox.io field array using `sstk_start_full_card` / `sstk_start_half_card` / `sstk_start_one_third_card` paired with `sstk_end_card`, and rendered through `get_fields_for_tab` rather than direct HTML echo.
- Remote operations go through `$this->execute_ssh('generic', $instance, ['commands' => ...])` after arguments are passed through `escapeshellarg`, never via direct shell invocation.
- Long-running or destructive actions enqueue work through `SSTK_POSTS_PENDING_TASKS_LOG()->add_pending_task_log_entry` and trigger it via `do_action('sstk_pending_log_*')` hooks instead of executing inline.
