Two layers coexist under `includes/core/apps/`: the shared base layer (`class-sstk-app.php`, `class-sstk-app-settings.php`, `class-sstk-ssh.php`) declares the lifecycle, script/token dispatch, REST command callback surface, and SSH/SFTP transport that every app must implement; the concrete app directories (`wordpress-app/`, `basic-server/`, `stable-diffusion/`, `vpn/`) plug into that contract by providing their own assets/templates/scripts plus a class extending the base. Cross-child wiring happens through the base class — child apps never talk to each other directly but are discovered and invoked via the shared app registry driven by the base classes. The WordPress app additionally extends the base with its own traits, REST controllers, admin tabs, and public UI, acting as the most feature-rich consumer of the contract while the other three apps remain thin providers focused on scripts and templates.
