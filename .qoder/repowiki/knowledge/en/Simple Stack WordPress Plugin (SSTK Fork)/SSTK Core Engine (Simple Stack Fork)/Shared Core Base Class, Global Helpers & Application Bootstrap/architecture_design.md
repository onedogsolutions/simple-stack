Three cooperating entry points under `includes/core/`:
- `class-sstk-base.php` defines `SSTK_Base`, a lightweight ancestor class offering shared helpers (`add_deferred_action_history`, `get_formatted_custom_links`) used by other domain classes.
- `functions.php` is a flat namespace of global helpers prefixed with `sstk_`: post/CPT queries, option accessors (`sstk_get_option`, `sstk_get_early_option`, `sstk_set_option`), nonce validators, string/line utilities, role/permission lookups (`sstk_user_can`, `sstk_get_posts_by_permission`), and feature-gate checks for authors (`sstk_can_author_view_server_feature`, `sstk_can_author_view_site_feature`).
- `simple-stack.php` defines `SSTK_CORE`, the application singleton (via `instance()` + `$GLOBALS['SSTK_CORE']`) that bootstraps the plugin: registers custom post types through lazy instantiation in `setup_post_types()`, loads roles/capabilities, hooks into `admin_menu` / `admin_enqueue_scripts` / `parent_file` / `submenu_file`, renders the Simple Stack React container, and manages the Vite build manifest at `assets/dist/.vite/manifest.json`. It also holds the provider registry (`$providers` keyed by slug) and exposes filters like `sstk_get_cloud_providers` and `sstk_os_list` so extensions can mutate behavior.

Dependency direction is one-way: `simple-stack.php` depends on `functions.php` helpers; `class-sstk-base.php` is independent and consumed by both. The module does not depend on any sibling domain classes except via lazy instantiation inside `SSTK_CORE::setup_post_types()`.
