Two-layer design centered on `class-sstk-rest-api.php` (the registrar) and `class-sstk-rest-controller-base.php` (the shared base). The registrar hooks `rest_api_init`, loads controller files via a static `load_files()` list, instantiates each class declared in its `$controllers` array, asserts it extends `SSTK_REST_Controller_Base`, and delegates route registration. Concrete controllers (`Servers`, `Sites`, `Logs`, `Tabs`, `Providers`, `Security`) extend the base and register routes exclusively through protected helpers (`register_get_route`, `register_post_route`, `register_delete_route`). The base enforces a uniform permission model — every route uses `permissions_check()` requiring `manage_options`, so no public permission callback is allowed. All responses go through `respond()`, which wraps data in `{ ok, data, meta }` and runs the payload through `SSTK_Secret_Redactor::redact()` before serialization. Parameter validation is centralized via typed helpers (`arg_id`, `arg_int`, `arg_string`, `arg_text`, `arg_object`, `arg_params`) that pair a `sanitize_callback` with a `validate_callback`; paging is normalized by `paging()`/`paging_args()` with a hard cap at `MAX_PER_PAGE = 200`. A legacy compatibility bridge (`dispatch_tab_action`) maps modern JSON params back onto `$_POST`/`$_FILES` and dispatches through the existing `sstk_app_*_tab_action` filter chain, preserving SSH key and file-upload quirks for older tab handlers. `class-sstk-secret-redactor.php` is a standalone utility loaded first by the registrar and used only as a response sanitizer — it has no REST awareness of its own.
