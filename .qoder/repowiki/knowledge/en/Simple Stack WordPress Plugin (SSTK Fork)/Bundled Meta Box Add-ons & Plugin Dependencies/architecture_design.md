Two distinct concerns coexist under this directory:

- Dependency declaration: `sstk-required-plugins.php` requires `class-tgm-plugin-activation.php` (a vendored copy of TGM Plugin Activation) and hooks into `tgmpa_register` to register the upstream `meta-box` plugin from the WordPress.org repository, with localized strings and an error nag type.
- Bundled add-ons: Each subdirectory is a self-contained WordPress plugin following the standard header + single entry file pattern (`mb-admin-columns.php`, `mb-custom-table.php`, `mb-settings-page.php`, `mb-term-meta.php`, `mb-user-meta.php`, `meta-box-group.php`, `meta-box-tooltip.php`, etc.). The larger add-ons (`mb-admin-columns`, `mb-custom-table`, `mb-settings-page`, `mb-term-meta`, `mb-user-meta`) ship their own `src/` namespace autoloaded via Composer's `vendor/autoload.php`, while smaller field add-ons (`meta-box-group`, `meta-box-tooltip`, `meta-box-tabs`, `meta-box-show-hide`, `meta-box-conditional-logic`, `meta-box-include-exclude`, `meta-box-columns`) are flat PHP files plus inline JS/CSS.

Every add-on guards against direct access with `defined('ABSPATH') || die`, checks for the host framework constant `RWMB_VER` (or class `RWMB_Group` / `RWMB_Field`) before bootstrapping, and registers itself on `init`/`admin_init` at priority 5 so it loads after the core Meta Box plugin. Larger add-ons define a package-level constant (`MBCT_DIR`/`MBCT_URL`, `MBSP_URL`) via `RWMB_Loader::get_path()` and instantiate a `Loader` plus feature classes (e.g. `Model\Ajax`, `Customizer\Manager`).
